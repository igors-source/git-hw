# Домашнее задание к занятию «Компоненты Kubernetes» "Шадрин Игорь"

### Цель задания

Рассчитать требования к кластеру под проект

### Задание. Необходимо определить требуемые ресурсы
Известно, что проекту нужны база данных, система кеширования, а само приложение состоит из бекенда и фронтенда. Опишите, какие ресурсы нужны, если известно:

1. Необходимо упаковать приложение в чарт для деплоя в разные окружения. 
2. База данных должна быть отказоустойчивой. Потребляет 4 ГБ ОЗУ в работе, 1 ядро. 3 копии. 
3. Кеш должен быть отказоустойчивый. Потребляет 4 ГБ ОЗУ в работе, 1 ядро. 3 копии. 
4. Фронтенд обрабатывает внешние запросы быстро, отдавая статику. Потребляет не более 50 МБ ОЗУ на каждый экземпляр, 0.2 ядра. 5 копий. 
5. Бекенд потребляет 600 МБ ОЗУ и по 1 ядру на копию. 10 копий.


### Решение 
Чтобы поддерживать доступность API, у кластера Kubernetes должно быть больше трех мастер-нод
Для того, чтобы кластер продолжал работать после выхода из строя одногй ноды, нужно минимум 3.
Рекомендованные требования для мастер - ноды:

-    4 CPU cores (Intel VT-capable CPU)

-    16GB RAM

###### Рекомендованные минимальные требования для воркер - ноды:

-    1 CPU cores (Intel VT-capable CPU)

-    8GB RAM

###### База данных:

*    Память: 4 Gb x 3  = 12 Gb
*    Ядра процессора: 1 Core x 3  = 3 Cores
-    Отказоустойчивость: Для обеспечения отказоустойчивости можно использовать реплицирование базы данных, для этого возможно поднять еще один экземпляр базы, которая будет зеркалить данные из 3х баз и в случае отказа станет матстером, итого 4 экземпляра баз данных

###### Система кеширования:

*    Объем памяти: 4 Gb x 3  = 12 Gb
*    Ядра процессора: 1 Core x 3  = 3 Cores
- Отказоустойчивость: Тут отказоустойчивость реализуем проще - в случае отказа - переключаемся напрямую к базе

###### Фронтенд:

*    Объем памяти: 50 Mb x 5 = 250 Mb
*    Ядра процессора: 0.2 Core x 5 = 1 Core

###### Бекенд:

*    Объем памяти: 600 Mb x 10 = 6 Gb
*    Ядра процессора: 1 Core x 10 = 10 Cores

###### Итог:

-    Общий объем памяти: 16 Gb (база данных+реплика) + 12 Gb (кеширование) + 250 Gb (фронтенд) + 6 Gb (бекенд) = 34.25 Gb ОЗУ
-    Общее количество ядер процессора: 4 (база данных+реплика) + 3 (кеширование) + 1 (фронтенд) + 10 (бекенд) = 17 Cores
-    Если мы хотим исспользовать Rolling update, необходимо предусмотреть состояние, когда в системе будут работать одновременно копии всех приложений, то есть умножаем требования памяти и процессора на 2
-    Для Мастер ноды необходимо 16х3 = 48 ГБ ОЗУ, 4х3=12 CPU, для worker ноды необходимо минимально 8х3=24 ГБ ОЗУ и 1х3 = 3 CPU
